## Problem

Grocery prices in New Zealand live on three websites built three different ways. Our ENGR302 team built [PricePath](https://price-path.online) to compare PAK'nSAVE, New World and Woolworths in Wellington: type a shopping list, see where it's cheapest and get a route through the shop.

I owned the scraper, and the hosting and deployment. The team built the React frontend and the Spring Boot backend.

Small project, real internet. I ran STRIDE over the scraper, the server and the deploy path, and kept one line per threat.

## Approach

The scraper is Python and Playwright. PAK'nSAVE and New World are both Foodstuffs sites built on Next.js, and each page already ships its data as JSON in a `__NEXT_DATA__` script tag, so the scraper reads that instead of the markup. Woolworths rebuilt its site in September 2026 with hashed CSS class names, so the scraper now replays the page's own GraphQL product search request.

Every run maps each chain's sections onto 8 shared categories, so "Bakery" means the same thing at all three. Rows with no name, no image or a bad price are dropped, and the backend reloads the data without a redeploy.

<Flow steps={["Store pages", "Playwright", "Validate", "JSON handoff", "Reload API"]} labels={["Source", "Scrape", "Check", "Hand off", "Serve"]} hot={1} />

Everything runs in Docker Compose on one Oracle Cloud VM with 4 cores and 24 GB of RAM, behind Cloudflare. Only nginx publishes ports to the internet:

```text title="docker compose ps · 1 Oct 2026" {2}
frontend   0.0.0.0:80->80/tcp, 0.0.0.0:443->443/tcp
backend    127.0.0.1:8080->8080/tcp
db         127.0.0.1:5433->5432/tcp
scraper
certbot
```

Deploys are pulled, not pushed. A systemd timer checks GitLab every 10 minutes with a read-only deploy key. If master moved, it backs up the data, rebuilds, health-checks the site and rolls back if the check fails. I chose that over a CI deploy job so no production SSH key ever goes into CI variables. A second timer checks the site, data age and disk every 15 minutes.

## Result

PricePath is live at [price-path.online](https://price-path.online). Woolworths refreshes every Monday at 03:00, and on 1 Oct 2026 the catalogue held 7,083 products, 491 of them matched across all three chains.

In the first 14.7 hours of monitoring, the health check passed 60 of 60 runs and nginx served 1,870 requests with no server errors. That's a short window, so it's a start rather than a track record.

## What I'd change

- Write the threat model in week one, not halfway through.
- Refresh PAK'nSAVE and New World automatically, instead of by hand from my laptop.
- Send health-check failures somewhere I'll see them. Right now they only reach the systemd journal.
- Keep each scrape's reload result somewhere that survives a container rebuild.
- Use a migration tool instead of Hibernate's `ddl-auto`.
