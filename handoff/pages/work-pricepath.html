01Problem

Grocery prices in New Zealand live on three websites built three different ways. Our ENGR302 team set out to build PricePath: type a shopping list, see where it's cheapest and get a route through the shop.

I owned two pieces. The scraper that pulls prices in every night, and the deployment that keeps the whole thing running. The course brief was a working product. My own brief was quieter: a scraper that never gets the team blocked, and a server nobody has to babysit.

02Threat model

Small project, real internet. I ran STRIDE over the scraper, the API box and the pipeline, then kept one line per threat so the team would actually read it.

SSpoofing

Only the CI runner can deploy. One SSH key per environment, password login off.

Mitigated
TTampering

Scraped rows are schema-checked before they reach the database.

Mitigated
RRepudiation

Every scrape run logs source, start time and row count.

Mitigated
IInfo disclosure

No secrets in the repo. CI variables are masked and protected.

Mitigated
DDenial of service

nginx rate limits requests. One small VM is still a single point of failure.

Accepted
EElevation

Services run as unprivileged users under systemd. No root in the app.

Mitigated

03Approach

PAK'nSAVE and New World are both Foodstuffs sites built on Next.js. Each page already ships its data as JSON in a __NEXT_DATA__ script tag, so the scraper reads that instead of guessing at markup. Woolworths needed real DOM scraping with Playwright locators.

Runs are polite: one store at a time, with a pause between pages. Every row passes a schema check before it's written, so a store redesign shows up as a failed run, not as bad prices.

The app runs on a single OCI instance behind nginx, with a DuckDNS domain and HTTPS. The GitLab pipeline lints, tests and deploys on every merge to main, over SSH with a deploy-only key.

04Dead ends

  1. 01

    TriedCalling the stores' internal APIs directly.

    Why notUndocumented, brittle and against the spirit of the sites' terms.

    NowRead only what the page already sends to any browser.

  2. 02

    TriedVisiting every product page.

    Why notSlow, and rude to the stores.

    NowCategory pages carry almost everything we need.

  3. 03

    TriedRunning the scraper as root on the API box.

    Why notOne bug away from owning everything.

    NowIts own unprivileged user and systemd unit. No sudo.

05Result

PricePath runs on HTTPS behind nginx. Prices refresh nightly across all three chains, and the pipeline ships every merge to main without anyone logging in to the server.

06What I'd change

  • Write the threat model in week one, not halfway through.
  • Swap DuckDNS for a real domain with DNSSEC and CAA records.
  • Alert when a store changes its markup, instead of finding out from an empty table.
  • Containerise the scraper so it isn't tied to one VM.
